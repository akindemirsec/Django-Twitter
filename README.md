# Django Twitter

A university-era full-stack social networking project with a Django REST API and
React interface. It demonstrates account registration, JWT authentication, and
basic social interactions. The original application design is retained for
portfolio review and local development.

## Features

- Register with a username, password, optional biography, location, birth date,
  and profile image; log in with JWT credentials.
- Publish text tweets of up to 280 characters and browse the global timeline.
- Like and unlike tweets from the home timeline.
- View user profiles and their tweets; follow and unfollow users.
- View notifications created by follows and likes.
- Access Django's administration interface with a superuser account.

The API also provides token refresh, tweet CRUD, and notification read endpoints;
the interface does not expose every API operation.

## Tech stack

- **Backend:** Python, Django 4.2, Django REST Framework, Simple JWT,
  django-cors-headers, Pillow.
- **Storage:** SQLite for application data and local files for profile images.
- **Frontend:** React 18, React Router 6, Axios, styled-components, React Icons,
  and Create React App (`react-scripts` 5).
- **Development containers:** Docker and Docker Compose.

## Requirements

- Python 3.11 and pip for the documented backend setup.
- Node.js and npm for the frontend. Its existing Dockerfile uses Node 16;
  newer Node versions have not been verified with this legacy toolchain.
- Alternatively, Docker with the Compose plugin for the container setup.

Dependencies retain the original versions rather than attempting a framework
upgrade. The Django-generated comments and migrations reference 5.0.7, while the
original dependency file selected Django 4.2; compatibility of a fresh migration
run remains to be verified. These legacy dependencies and development settings
are not a production deployment baseline.

## Local setup

Run commands from the repository root unless a different directory is shown.

### 1. Configure a Python environment

```sh
python -m venv .venv
```

Activate it with `.venv\Scripts\Activate.ps1` in PowerShell, or
`source .venv/bin/activate` on macOS/Linux. Then install dependencies:

```sh
python -m pip install -r requirements.txt
```

### 2. Configure the environment

Copy `.env.example` to `.env` and replace its `DJANGO_SECRET_KEY` placeholder with
a private value generated by:

```sh
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

Keep `.env` private. Django requires `DJANGO_SECRET_KEY`; `DEBUG` defaults to `1`
and `DJANGO_ALLOWED_HOSTS` defaults to `localhost 127.0.0.1` (space separated).
The application uses SQLite directly, so no `DATABASE_URL` or PostgreSQL service
is needed. Changing the key invalidates existing signed tokens.

Django does not automatically read `.env`. Load it into the current shell before
running backend commands. In PowerShell:

```powershell
Get-Content .env | ForEach-Object {
    if ($_ -match '^([A-Za-z_][A-Za-z0-9_]*)=(.*)$') {
        [Environment]::SetEnvironmentVariable($Matches[1], $Matches[2], 'Process')
    }
}
```

Or in Bash (only source your own trusted configuration):

```sh
set -a
source .env
set +a
```

### 3. Start the API

```sh
cd twitter_clone
python manage.py migrate
python manage.py createsuperuser  # optional, for /admin/
python manage.py runserver 127.0.0.1:8000
```

The API is at http://127.0.0.1:8000/api/ and the admin at
http://127.0.0.1:8000/admin/. Migrations create the local SQLite database if absent.
Existing local databases and uploaded images are not required for a fresh setup.

### 4. Start the frontend

In a second terminal, from the repository root:

```sh
cd twitter-clone-frontend
npm ci
npm start
```

Open http://localhost:3000/register, create an account, then log in at `/login`.
Use `localhost:3000` because it is the configured CORS origin. Frontend requests
currently use the fixed API address `http://127.0.0.1:8000`.

## Docker development setup

Prepare the root `.env` as above; Compose loads it for the backend automatically.
Then run from the repository root:

```sh
docker compose build
docker compose run --rm django python manage.py migrate
docker compose up
```

Open http://localhost:3000/register. The API is exposed on port 8000. Both services
run development servers. Backend source, SQLite data, and uploads use the local
`twitter_clone/` bind mount; frontend dependencies use a separate container
volume so the source bind mount does not hide them.

## Project structure

```text
.
|-- twitter_clone/
|   |-- manage.py
|   |-- twitter_clone/         # Django settings and API routes
|   `-- tweets/                # Models, serializers, views, signals, migrations
|-- twitter-clone-frontend/
|   |-- public/                # HTML template and public images
|   |-- src/components/        # Authentication, timeline, profiles, notifications
|   |-- src/styles/            # styled-components theme and global styles
|   `-- package.json
|-- requirements.txt
|-- .env.example
|-- Dockerfile
`-- docker-compose.yml
```

`djangotwitter/`, if present in an old checkout, is a machine-specific Python
virtual environment, not application source. It is ignored; create `.venv/` for
your own installation. Local databases, uploads, caches, and build output are
also ignored. Ignore rules do not remove files already tracked in a repository.

## Checks and known limitations

```sh
# From twitter_clone/, with the backend environment configured:
python manage.py check
python manage.py test

# From twitter-clone-frontend/:
npm test -- --watchAll=false
npm run build
```

Backend tests are currently an empty scaffold. The frontend includes a login
rendering smoke test; there is no end-to-end test suite.

- Access tokens expire after five minutes. The frontend stores the access token
  in localStorage and does not automatically refresh it or provide logout.
- The existing private-route component is not wired into the route table.
- Profile editing, search, replies, and real-time updates are not implemented.
- The tweet API currently checks authentication but does not restrict update or
  deletion to the tweet author. Review authorization before any public deployment.
- Development mode and local media serving are intended for local demonstration.

This is a social application prototype, not a deliberately vulnerable security
training project. Runtime, clean dependency installation, migrations, frontend
build, and Docker startup have not been verified during this repository cleanup.
